## 项目方向

本项目是一个以《欧罗巴共和国宪法》为核心的宪政模拟工程，分成两层来做：

- **宪政模型层**：负责描述宪法里的对象、机关、程序和规则
- **语言实现层**：负责展示 C、老C++、现代C++、32-64 x86 ASM 的特性

项目的目标不是只写一份宪法文本，而是把它做成一个可展开、可验证、可演化的工程。

## 项目总目标

README.md 里的内容主要承担这些职责：

- 说明这是“一部融合欧洲的法国、德国、意大利等宪政制度”的宪法
- 说明这是“单一制、双首长制、内阁制，动态换轨”的制度设计
- 说明“大换轨”和“小换轨”的概念
- 作为《欧罗巴共和国宪法》的正文底稿
- 保留“用 C/老C++/现代C++/32-64 x86 ASM 实现”的总说明

## 目录分工

### `include/c/`

这一层放纯 C 的基础接口，尽量贴近你原来“c with class”的写法。

- `constitution.h`：宪法总入口
- `types.h`：类型定义
- `macros.h`：宏定义
- `result.h`：结果与状态返回
- `registry.h`：注册表、总线、链表式对象管理
- `member.h`：公民、议员、成员
- `seat.h`：席位、席次、分配单位
- `body.h`：议会体、委员会、合议体
- `office.h`：总统、总理、议长、主席等单一职务
- `procedure.h`：选举、任命、解散、复决、弹劾、修正等程序
- `document.h`：法案、命令、决议、修正案等文书
- `election.h`：选举规则和选举流程
- `referendum.h`：公民复决
- `impeachment.h`：弹劾、罢免、缺位处理
- `law.h`：法律、立法、普通立法处理
- `court.h`：司法、宪法法院、违宪审查

### `include/cpp/`

这一层放对应的 C++ 接口，和 C 层表达同一套宪法对象，但用 `class`、继承和虚函数去包装。

它不是替代 C 层，而是并行展示同一套模型。

### `src/c/`

这里放 C 的核心实现。

C 层更适合放：

- `struct`
- 函数指针
- 宏驱动的对象实例化
- 链表 / 注册表
- 动态内存
- 规则和状态机

### `src/cpp/`

这里放 C++ 的高层封装和对象组织。

C++ 层更适合放：

- `class`
- 继承
- 虚函数
- 构造 / 析构
- 少量包装层
- 更清晰的对象模型

### `asm/`

这里放 `func.asm`，用于汇编实验、底层优化或特殊流程演示。

### `tests/`

- `tests/c/`：验证 C 层逻辑
- `tests/cpp/`：验证 C++ 层逻辑

### `docs/`

- `architecture.md`：项目方向、目录分工、实现路线
- `syntax-map.md`：C/C++ 特性映射
- `constitution-model.md`：宪法正文的模型拆分

## 模块抽象

为了避免“按名字堆文件”，项目应该先抽象共同点，再挂具体机关。

### 最小原子

建议先把宪法拆成这些原子：

- `member`：公民、议员、候选人等成员
- `seat`：席位
- `body`：共和国议会、大区议会、省议会、广域市议会、公社委员会等合议体
- `office`：总统、总理、议长、主席等单一职务
- `procedure`：选举、任命、解散、复决、弹劾、修宪
- `document`：法案、命令、决议、修正案
- `registry`：对象总线、链表、注册表
- `rule`：选举规则、表决门槛、任期、改选规则

### 机关层

这些原子再组合成具体机关：

- `总统`
- `总理`
- `内阁`
- `国家议会`
- `共和国议会`
- `大区议会`
- `省议会`
- `广域市议会`
- `公社委员会`
- `宪法法院`
- `地方单位`

### 程序层

这些程序负责描述“怎么发生变化”：

- 选举
- 任命
- 解散
- 公民复决
- 弹劾
- 违宪审查
- 解释
- 条款暂停

### 文书层

这些文书负责描述“系统产出什么”：

- 法案
- 修正案
- 命令
- 决议
- 条约
- 复议请求

## 实现路线

建议按这个顺序推进：

1. 先完成 `types`、`result`、`macros`、`registry`
2. 再完成 `member`、`seat`、`body`、`office`
3. 再完成 `procedure`、`document`、`election`
4. 再完成 `referendum`、`impeachment`、`law`、`court`
5. 最后补 `cpp` 包装层和 `asm` 特性

## 与 README.md 的关系

README.md 保留原始宪法正文和总说明，`docs/` 负责把正文拆成可实现的模型。

换句话说：

- README.md 写“是什么”
- `architecture.md` 写“怎么分”
- `syntax-map.md` 写“用什么语言特性做”
- `constitution-model.md` 写“正文如何映射到代码对象”
